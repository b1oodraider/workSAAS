# Передача работы в новую сессию

Прочитай целиком перед началом. Обновлено: 2026-10-08.

## Что это

workSAAS — self-hosted аналог Sofi agent / JobPath / Hirify для владельца и <5 друзей
(ноутбук Ryzen 7 4340U / 16 ГБ или дешёвый VPS). Возможности: подбор вакансий по резюме
(28 источников: российские доски, Telegram-каналы, зарубежные удалённые доски, карьерные страницы компаний —
список в README «Источники вакансий»; импорт по ссылке),
оценка вакансий и резюме, сопроводительные письма, трекер откликов, Telegram-бот, автоотклики на hh.ru.

- Как устроено: `docs/ARCHITECTURE.md` (слои, точки расширения, рецепты).
- Правила для агентов: `CLAUDE.md` (обязательно), агенты-критики — `.claude/agents/`.
- Для пользователя: `README.md`; оплата LLM из РФ: `reports/Оплата LLM из России 2026.md`.
- Выбор моделей и три плана расходов: **`docs/LLM_PLANS.md`**.

## Что делать дальше (по порядку)

1. **Подключить Cloud.ru.** Скопировать общий блок провайдера из `docs/LLM_PLANS.md` в `config.toml`,
   ключ — `CLOUDRU_API_KEY` в `.env`. Проверить: `worksaas doctor --llm` (один дешёвый запрос на модель).
   Уточнить, работает ли `json_mode = "json_object"`; если нет — `"none"`.
   В облачной сессии домен `foundation-models.api.cloud.ru` был закрыт сетевой политикой — локально проблем нет.
2. **Тест писем — СДЕЛАН 2026-10-08: письма на `zai-org/GLM-5.1`** (итоги — `docs/LLM_PLANS.md`, раздел «Тест писем вслепую»). Как повторить: Команда: `worksaas compare-letters <логин>` (без параметров покажет
   id резюме и вакансий), затем `worksaas compare-letters <логин> --resume 1 --vacancy 12 --vacancy 15 ...`
   (4–5 разных реальных вакансий). По умолчанию 5 кандидатов Cloud.ru: `GigaChat/GigaChat-3-Pro`,
   `ai-sage/GigaChat3.5-432B-A28B-Reasoning`, `moonshotai/Kimi-K2.6`, `deepseek-ai/DeepSeek-V4-Pro`,
   `zai-org/GLM-5.1` (другие — `--model провайдер:модель`). 5 вакансий × 5 моделей ≈ 25 писем, < 100 ₽.
   Письма пишутся обычным конвейером `cover_letter` (те же промпт и переменные), в анализы не сохраняются;
   отчёт — `data/letter-tests/<дата>/`: `blind.md` (письма вслепую, перемешаны), `key.md` (модель, токены,
   цена), `inputs.md`. **Обязательно**: субагент «альтернативное мнение» оценивает `blind.md` + `inputs.md`,
   не видя `key.md`: конкретика из резюме, отсутствие выдумок, соответствие вакансии, живой русский язык,
   длина для отклика на hh.ru. Сравнить его выводы со своими, расхождения показать владельцу.
   Итог — модель для роли «Письма» в `docs/LLM_PLANS.md`.
3. **Только после выбора модели писем** — тест оценки вакансий (`match`): `openai/gpt-oss-120b` vs
   `deepseek-ai/DeepSeek-V4-Flash` (и V4.1-Flash, если имя подтвердится) на тех же вакансиях:
   стабильность баллов, адекватность gaps/рекомендаций, валидность JSON, реальная стоимость
   (смотреть `/usage` — сколько выходных токенов уходит на «размышления»).
4. Вписать итоговый план в `config.toml`/`config.example.toml`, цены — в `[llm.prices]`
   (варианты учёта в рублях — в `docs/LLM_PLANS.md`), лимиты пользователям — `worksaas set-budget`.
5. **Живые проверки на ПК** (из облака сайты были недоступны, всё проверено только на образцах):
   `worksaas doctor` (источники, бот); поиск hh.ru в режиме `auto`; автоотклики — сначала режим
   «спрашивать перед каждым откликом» и `[apply] headless = false`, наблюдать за браузером; селекторы
   hh.ru при необходимости править в `[apply.hh_selectors]`. Вход: `worksaas site-login hh <логин>`.

  вперёд. **Разметка страницы hh.ru не проверена вживую** — проверить на ПК; селектор `negotiations_item`.

## Сделано 2026-10-08

- **28 источников** (было 9): российские доски, 20 проверенных Telegram-каналов по умолчанию, зарубежные
  удалённые доски, карьерные страницы компаний (Greenhouse/Lever/Ashby), LinkedIn (гостевой, выключен).
  Список и статус проверки — README «Источники вакансий». Разметка проверена вживую 2026-10-08 (кроме Adzuna).
- **Условия поиска** у резюме (`resumes.criteria`, миграция 0007): реальная минималка, страны, формат, переезд,
  языки, гражданство, грейд, «на ступень выше», смежные роли, отрасли «нет». Минималка/удалёнка/отрасли
  сужают все поиски; остальное — в `<preferences>` (письма работодателю их приватную часть не видят).
- **Смежные роли и мягкий грейд:** профиль резюме выдаёт `adjacent_roles` (2 идут в поисковые запросы,
  в префильтре — 60% балла за название); в оценке «3+ года» при 2 годах — вычет 5–10, а не отсев.
- Источники опрашиваются параллельно (до 4).
- **Отбор по смыслу (эмбеддинги)**, с согласия владельца: `[llm.embeddings]` (Cloud.ru `BAAI/bge-m3`), по
  умолчанию выключен. Балл отбора = 50% слова + 50% сходство с резюме по смыслу — находит вакансии на
  другом языке, синонимы, смежные названия. Векторы — в `embedding_cache` (миграция 0008), каждый текст
  оплачивается один раз на всех; `user_vacancies.semantic_score` — колонка «Смысл» на странице поиска.
  `prefilter_score` остался только словами (на нём держится защита режима автооткликов «auto»).
  Порог перевода косинуса в баллы (`low`/`high`) — оценка, проверить на живых вакансиях.
- **`worksaas compare-letters`** — тест моделей писем вслепую (см. шаг 2).
- Промпт письма v5 (без выдуманного «изучаю X», коммерческого опыта, сроков, личных деталей; ответы на вопросы
  работодателя), letter_critic v3 ловит то же. Автоотклики не отправляют без просмотра письмо с повреждённым текстом
  (склеенные кириллица и латиница, обрывки кода — так ломается DeepSeek-V4-Pro). hh.ru: отказ «bad_user_agent» → разбор сайта.

## Как развернуть локально (Windows)

```powershell
git clone https://github.com/b1oodraider/worksaas workSAAS
cd workSAAS
git checkout claude/inspiring-bardeen-p0ikq1
python -m venv .venv
.venv\Scripts\pip install -e ".[dev,browser]"
.venv\Scripts\playwright install chromium
copy config.example.toml config.toml   # затем правки из docs/LLM_PLANS.md
# .env: WS_SECRET_KEY, WS_TELEGRAM__BOT_TOKEN, CLOUDRU_API_KEY
.venv\Scripts\worksaas init-db
.venv\Scripts\worksaas create-user <логин> --admin
.venv\Scripts\worksaas run
```
