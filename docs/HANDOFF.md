# Передача работы в новую сессию

Прочитай целиком перед началом. Обновлено: 2026-09-30 (вечер).

## Что это

workSAAS — self-hosted аналог Sofi agent / JobPath / Hirify для владельца и <5 друзей
(ноутбук Ryzen 7 4340U / 16 ГБ или дешёвый VPS). Возможности: подбор вакансий по резюме
(hh.ru без API-ключа, Хабр, trudvsem, superjob, Telegram-каналы, RSS, remotive, remoteok, импорт по ссылке),
оценка вакансий и резюме, сопроводительные письма, трекер откликов, Telegram-бот, автоотклики на hh.ru.

- Как устроено: `docs/ARCHITECTURE.md` (слои, точки расширения, рецепты).
- Правила для агентов: `CLAUDE.md` (обязательно), агенты-критики — `.claude/agents/`.
- Для пользователя: `README.md`; оплата LLM из РФ: `reports/Оплата LLM из России 2026.md`.
- Выбор моделей и три плана расходов: **`docs/LLM_PLANS.md`**.

## Сделано 2026-10-01

- Промпты не привязаны к IT: работают для любой профессии. Общие правила о стаже и датах вынесены в `_common.j2`.
- Профиль резюме: роли с синонимами (RU/EN и широкие названия), 4–8 запросов (`MAX_QUERIES = 8`).
- Дата публикации: префильтр отсекает вакансии старше периода (для всех источников) и понижает старые;
  дата видна в вебе и в боте. В промпт дата не попадает: иначе перепубликация на hh ломала бы кэш.
- 👍/👎 оценке ИИ с причиной (веб и бот; в боте 👎 скрывает вакансию, ⭐ засчитывается как 👍).
  Тип отказа работодателя (шаблонный / с объяснением).
- Оценка компаний (`services/companies.py`) — только по своим данным, от 3 разных пользователей,
  без счётчиков (приватность); только доверенные источники; ±5 к сортировке.
- Прогнаны все 11 ИИ-функций на двух резюме: Java и синтетический менеджер по продажам. Было три раунда
  слепой проверки субагентами; промпты правились по их замечаниям. Что закрыто: текущая дата в промптах (месяц),
  «не указано ≠ нет», слова вакансии не становятся фактами, стаж только по профессии, потолки грейда 2x/5x,
  тип работы и модель дохода в `match`, сценарий мошенничества в `recruiter_reply`, контрпредложение без якоря
  вниз в `offer_negotiation`, род кандидата.
- **Живой hh.ru:** страница поиска больше не отдаёт отрывки описаний. Теперь поиск догружает полные тексты
  top_n × 3 лучших кандидатов (`FULL_TEXT_FACTOR`) перед выбором для ИИ. Из карточки берётся требуемый опыт;
  вакансии «от 3 лет» при стаже в 2+ раза меньше понижаются в префильтре.
- Шлюз повторяет вызов на той же модели один раз при битом JSON и только потом уходит на резервную модель.
  V4.1-Flash на Cloud.ru иногда возвращает битый JSON; режим `json_schema` Cloud.ru для неё молча игнорирует.

## Известные проблемы ИИ (после тестов)

- `max_tokens` на Cloud.ru не ограничивает «размышления»: `tailor_resume` с effort=low однажды потратил
  14 тыс. токенов (3 ₽). С effort=none он дешевле, но выдумывает («переписку веду»), поэтому effort=low оставлен.
- Промптом не лечатся: длина письма иногда 850 знаков при лимите 800 и редкие опечатки. Нужен валидатор
  с повторной генерацией — не сделано.
- Оставшиеся мелкие выдумки: навыки из списка приписываются стажировке, «сэндвичи = длинные сделки».
  Резервная GigaChat3.5 отвечает до 6 минут — годится только как запасная.

## Как развернуть локально (Windows)

```powershell
git clone https://github.com/b1oodraider/worksaas workSAAS
cd workSAAS
git checkout claude/inspiring-bardeen-p0ikq1
python -m venv .venv
.venv\Scripts\pip install -e ".[dev,browser]"
.venv\Scripts\playwright install chromium
copy config.example.toml config.toml   # затем правки из docs/LLM_PLANS.md
# .env: WS_SECRET_KEY, WS_TELEGRAM__BOT_TOKEN, CLOUDRU_API_KEY
.venv\Scripts\worksaas init-db
.venv\Scripts\worksaas create-user <логин> --admin
.venv\Scripts\worksaas run
```
