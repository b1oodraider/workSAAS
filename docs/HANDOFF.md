# Передача работы в новую сессию

Прочитай целиком перед началом. Обновлено: 2026-09-30.

## Что это

workSAAS — self-hosted аналог Sofi agent / JobPath / Hirify для владельца и <5 друзей
(ноутбук Ryzen 7 4340U / 16 ГБ или дешёвый VPS). Возможности: подбор вакансий по резюме
(hh.ru без API-ключа, Хабр, trudvsem, superjob, Telegram-каналы, RSS, remotive, remoteok, импорт по ссылке),
оценка вакансий и резюме, сопроводительные письма, трекер откликов, Telegram-бот, автоотклики на hh.ru.

- Как устроено: `docs/ARCHITECTURE.md` (слои, точки расширения, рецепты).
- Правила для агентов: `CLAUDE.md` (обязательно), агенты-критики — `.claude/agents/`.
- Для пользователя: `README.md`; оплата LLM из РФ: `reports/Оплата LLM из России 2026.md`.
- Выбор моделей и три плана расходов: **`docs/LLM_PLANS.md`**.

- **Не выходить за пределы папки проекта** (касается существующих файлов; ставить пакеты через pip

- Секреты только в `.env` (в git не попадает): `WS_SECRET_KEY`, `WS_TELEGRAM__BOT_TOKEN`,
  `CLOUDRU_API_KEY`. **Никогда не печатать, не коммитить, не присылать значения** (проверять только имена).

## Что делать дальше (по порядку)

1. **Подключить Cloud.ru.** Скопировать общий блок провайдера из `docs/LLM_PLANS.md` в `config.toml`,
   ключ — `CLOUDRU_API_KEY` в `.env`. Проверить: `worksaas doctor --llm` (один дешёвый запрос на модель).
   Уточнить, работает ли `json_mode = "json_object"`; если нет — `"none"`.
   В облачной сессии домен `foundation-models.api.cloud.ru` был закрыт сетевой политикой — локально проблем нет.
2. **Тест писем — сначала только он.** Кандидаты: `GigaChat/GigaChat-3-Pro`, `deepseek-ai/DeepSeek-V4-Pro`,
   `deepseek-ai/DeepSeek-V4-Flash`. Вход: резюме владельца + 4–5 реальных вакансий (попросить тексты
   или ссылки hh.ru). ~12 писем ≈ 8 ₽. Письма пишутся через обычный конвейер (`run_analysis("cover_letter")`,
   маршрут `cover_letter` переключать по очереди), чтобы тестировать ровно то, что пойдёт в работу.
   **Обязательно**: субагент «альтернативное мнение» — получает письма вслепую (без названий моделей,
   в случайном порядке) и независимо оценивает: конкретика из резюме, отсутствие выдумок, соответствие
   вакансии, живой русский язык, длина для отклика на hh.ru. Сравнить его выводы со своими, расхождения
   показать владельцу. Итог — модель для роли «Письма» в `docs/LLM_PLANS.md`.
3. **Только после выбора модели писем** — тест оценки вакансий (`match`): `openai/gpt-oss-120b` vs
   `deepseek-ai/DeepSeek-V4-Flash` (и V4.1-Flash, если имя подтвердится) на тех же вакансиях:
   стабильность баллов, адекватность gaps/рекомендаций, валидность JSON, реальная стоимость
   (смотреть `/usage` — сколько выходных токенов уходит на «размышления»).
4. Вписать итоговый план в `config.toml`/`config.example.toml`, цены — в `[llm.prices]`
   (варианты учёта в рублях — в `docs/LLM_PLANS.md`), лимиты пользователям — `worksaas set-budget`.
5. **Живые проверки на ПК** (из облака сайты были недоступны, всё проверено только на образцах):
   `worksaas doctor` (источники, бот); поиск hh.ru в режиме `auto`; автоотклики — сначала режим
   «спрашивать перед каждым откликом» и `[apply] headless = false`, наблюдать за браузером; селекторы
   hh.ru при необходимости править в `[apply.hh_selectors]`. Вход: `worksaas site-login hh <логин>`.

## Как развернуть локально (Windows)

```powershell
git clone https://github.com/b1oodraider/worksaas workSAAS
cd workSAAS
git checkout claude/inspiring-bardeen-p0ikq1
python -m venv .venv
.venv\Scripts\pip install -e ".[dev,browser]"
.venv\Scripts\playwright install chromium
copy config.example.toml config.toml   # затем правки из docs/LLM_PLANS.md
# .env: WS_SECRET_KEY, WS_TELEGRAM__BOT_TOKEN, CLOUDRU_API_KEY
.venv\Scripts\worksaas init-db
.venv\Scripts\worksaas create-user <логин> --admin
.venv\Scripts\worksaas run
```
