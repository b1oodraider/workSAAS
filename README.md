# workSAAS

Self-hosted помощник по поиску работы для себя и нескольких друзей (веб-интерфейс + Telegram-бот).

**Главное**
- **Подбор вакансий по резюме** — ИИ составляет профиль и поисковые запросы → вакансии собираются
  из 28 источников (hh.ru, Хабр Карьера, «Работа России», Работа.ру, Telegram-каналы, зарубежные доски,
  карьерные страницы компаний — таблица ниже) →
  дубли между источниками склеиваются → бесплатный префильтр → ИИ оценивает только лучшие.
  Поиски можно запускать по расписанию, новые сильные совпадения приходят в Telegram.
- **Оценка резюме** — разбор глазами рекрутера, исправления, ключевые слова, блок «О себе».
- **Оценка вакансии** — красные/зелёные флаги с цитатами, реальные требования, вопросы работодателю.
- **Сопроводительные письма** — под вакансию, с учётом анализа соответствия, без выдуманных фактов.

**Дальше по воронке**
- Проверка письма (ваше или сгенерированное) критиком-рекрутером.
- Адаптация резюме под вакансию — точечные правки с пометкой, что заявлять нельзя.
- Подготовка к интервью: вероятные вопросы с планом ответа на ваших фактах.
- Трекер откликов: воронка, напоминания «неделя тишины», follow-up письма, ответ рекрутеру, разбор оффера.

**Для компании друзей**: логины без регистрации, месячный лимит расходов на ИИ у каждого, кэш
ответов (одна и та же вакансия не оплачивается дважды), админка, учёт расходов.

Архитектура и правила расширения: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).
Чем платить за ИИ из России: [reports/Оплата LLM из России 2026.md](reports/Оплата%20LLM%20из%20России%202026.md).

## Быстрый старт (ноутбук)

Нужен Python 3.12+.

```bash
git clone <repo> worksaas && cd worksaas
python -m venv .venv && source .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -e .

cp .env.example .env                 # WS_SECRET_KEY, ключ LLM, токен бота
cp config.example.toml config.toml   # провайдер LLM, источники

worksaas create-user me --admin      # спросит пароль
worksaas doctor                      # проверит ключи, доступность сайтов, бота
worksaas doctor --llm                # + пробный запрос к модели (доли цента)
worksaas run                         # http://127.0.0.1:8000
```

Остальных пользователей удобнее создавать в «Админке» (пароль сгенерируется и покажется один раз).
Без ключа LLM интерфейс можно пощупать, направив маршрут на заглушку:
```toml
[llm.routes.default]
provider = "fake"
model = "fake"
```

## LLM: чем платить

Прямой доступ к Claude/GPT/Gemini из России закрыт (подробно — в отчёте выше). В `config.example.toml`
есть готовые заготовки:

| Вариант | Как подключить |
|---|---|
| Claude через реселлера за рубли (AITunnel, ProxyAPI) | `type = "anthropic"`, `base_url`, `auth_scheme = "bearer"`, `price_multiplier` = наценка |
| Cloud.ru (GigaChat, Qwen, GLM), Yandex AI Studio | `type = "openai_compat"`, `base_url` |
| DeepSeek, локальная Ollama / LM Studio | `type = "openai_compat"` |
| Anthropic напрямую (иностранная карта и сервер вне РФ) | `type = "anthropic"` |

Каждой функции можно назначить свою модель (`[llm.routes.<функция>]`), а маршруту — резервных
провайдеров (`fallbacks`), которые включатся, если основной недоступен.
**Адреса и форматы авторизации реселлеров не проверены запросом** — сверьтесь с их документацией.

Грубая оценка стоимости (не измерена на реальном API): один анализ ≈ 4 тыс. входных и 1,5 тыс.
выходных токенов; на `claude-opus-5-5` по официальным ценам — $0.03–0.08, у реселлеров в 2–4 раза
дороже. Рычаги: `matching.top_n`, `effort` в маршрутах, модель для `match`, лимиты пользователей.
Фактические расходы видны на странице «Расходы» и в «Админке».

## Telegram-бот

1. Создайте бота у [@BotFather](https://t.me/BotFather), токен — в `.env`: `WS_TELEGRAM__BOT_TOKEN=...`
2. Для ссылок из бота на веб-интерфейс укажите адрес: `[telegram] public_url = "https://jobs.example.com"`.
3. Перезапустите `worksaas run`. Каждый пользователь в «Настройках» нажимает «Привязать Telegram».

Бот: присылаете ссылку или текст вакансии — получаете оценку и соответствие резюме с кнопками
«Сопроводительное / Сохранить / Откликнулся / Скрыть»; присылает новые сильные совпадения
(порог — `/notify 80`) и напоминания трекера. Команды: `/top`, `/searches`, `/resumes`, `/usage`,
`/autoapply` (автоотклики: письма на подтверждение, отчёты, пауза).
Бот работает только в личных чатах. Токен не пишется в логи.

Один токен может опрашивать только **один** процесс. Если бот нужен отдельно от веба:
`[telegram] enabled = false` в конфиге веба и `worksaas bot` отдельным процессом.

«Не проверено вживую» значит: парсеры покрыты тестами на образцах формата, но сами сайты из среды
разработки были недоступны. Если источник сломается, поиск не упадёт — ошибка появится в результате
задачи и в «Админке», остальные источники отработают.

**Браузерный режим** (для hh.ru при капче/защите от ботов):
```bash
pip install -e ".[browser]"
playwright install chromium
```
и в конфиге `[sources.hh.options] fetcher = "auto"` (или `"browser"`). Не уменьшайте `min_interval`:
частые запросы — самый быстрый способ получить блокировку.

## Автоотклики (hh.ru)

Не массовая рассылка, а медленная очередь из лучших совпадений:

1. **Отбор.** В очередь попадают только вакансии из ваших поисков с оценкой ИИ не ниже порога
   (по умолчанию 80). Исключаются вакансии с рекомендацией «пропустить», с серьёзными красными
   флагами в разборе вакансии и те, по которым вы уже что-то решили в трекере.
2. **Письмо.** Для каждой вакансии заранее пишется своё короткое сопроводительное в выбранном тоне.
   Ваши «пожелания к работе» (зарплата и т.п.) в него не попадают. Письмо со ссылками или контактами,
   которых нет в резюме, всегда ждёт вашей проверки (защита от «инструкций» в тексте вакансии).
3. **Отправка.** Отклики уходят по одному: не чаще раза в N минут со случайным разбросом, не больше
   M в сутки и только в выбранные часы. Жёсткие потолки для всех — в `[apply]`
   (по умолчанию 30 в сутки и не чаще раза в минуту).
4. **Режимы.** «Спрашивать перед каждым откликом»: письмо приходит в Telegram или показывается
   на странице «Автоотклики», вы подтверждаете именно этот текст. «Откликаться автоматически»:
   отклики уходят сами, в боте приходят отчёты.
5. **Автопауза.** Капча, выход из аккаунта, кончившийся бюджет LLM или 3 ошибки подряд ставят
   автоотклики на паузу. Бот пришлёт сообщение с кнопкой «Продолжить».
6. **Что пропускается.** Вакансии с анкетой работодателя, закрытые вакансии и вакансии, на которые
   вы уже откликались, остаются для ручного отклика. Успешный отклик сам отмечается в трекере.

**Вход в hh.ru** (пароль приложению не передаётся, сохраняются только cookies hh.ru):
```bash
pip install -e ".[browser]" && playwright install chromium
worksaas site-login hh ВАШ_ЛОГИН                     # откроется окно браузера — войдите как обычно
worksaas site-login hh --export session.json          # если приложение на сервере: войти у себя,
                                                      # затем загрузить файл на странице «Автоотклики»
```
Файл сессии лежит в `data/sessions/` с правами 0600 и даёт доступ к аккаунту hh.ru. Храните его
как пароль, удалить можно кнопкой на странице. В `worksaas backup` сессии не входят: после
восстановления войдите заново. Запускайте `site-login` из той же папки, что и сервер (`data_dir`
по умолчанию относительный). Если сервер за границей, может понадобиться
`[apply] use_proxy = true` с российским `proxy_url`: вход в аккаунт с неожиданной страны
подозрителен.

⚠️ **Риски.** Автоматические отклики противоречат правилам hh.ru, и даже в медленном режиме аккаунт
могут ограничить. Режим с подтверждением безопаснее. Селекторы страниц hh.ru написаны по известной
разметке, **на живом сайте не проверены** (из среды разработки hh.ru недоступен), а флоу проверен
только на локальной копии разметки. Если hh.ru поменяет вёрстку, отклики будут падать с ошибкой и
встанут на паузу. Поправить селекторы можно в `[apply.hh_selectors]` без изменения кода. Первые
отклики лучше сделать в режиме с подтверждением и `headless = false`, наблюдая за браузером.

## VPS (Docker + HTTPS)

```bash
cp .env.example .env && cp config.example.toml config.toml   # заполнить
mkdir -p data && sudo chown 1000:1000 data                    # контейнер работает не от root
docker compose up -d --build
docker compose exec app worksaas create-user me --admin
```

Контейнер слушает только `127.0.0.1:8000`; HTTPS проще всего через [Caddy](https://caddyserver.com/):
```
jobs.example.com {
    reverse_proxy 127.0.0.1:8000
}
```
`[telegram] public_url` должен быть тем адресом, который видит браузер (`https://jobs.example.com`, без
внутреннего порта): по нему cookie сессии становятся Secure и проверяется, что формы отправлены с этого же
сайта (иначе POST-запросы получают 403 «отправлен с другого сайта», причина пишется в лог).
Если вместо Caddy стоит nginx, он должен передавать исходный адрес сайта:
```
location / {
    proxy_pass http://127.0.0.1:8000;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```
В Docker задайте `trusted_proxies` = адрес шлюза docker-сети (см. комментарий в `config.example.toml`),
иначе ограничение попыток входа будет считать всех пользователей одним IP. Размер сервера — ниже,
«Какой сервер нужен».

## Какой сервер нужен

Оценка на 5–10 человек (2026-10-08, по устройству приложения, нагрузочно не замерялась). ИИ и эмбеддинги
считаются у провайдера, сервер только ходит по сайтам, разбирает страницы и хранит базу.

| | Минимум | Рекомендуется |
|---|---|---|
| CPU | 1 vCPU | 2 vCPU — браузер для автооткликов и разбор страниц не мешают веб-интерфейсу |
| RAM | 1 ГБ — без браузера (`WITH_BROWSER=0`), автоотклики не работают | 2 ГБ: приложение ~250–300 МБ, один Chromium ~400 МБ (одновременно запускается только один), ОС, Docker, Caddy |
| Диск | 15 ГБ SSD | 30–40 ГБ SSD: образ с Chromium ~1,5 ГБ, база растёт примерно на сотни МБ в месяц (тексты вакансий), бэкапы — копии базы |
| Сеть | любой безлимит | — |

- **Где:** в России. Резюме — персональные данные граждан РФ (152-ФЗ: хранение в РФ), hh.ru и автоотклики
  лучше с российского IP, Cloud.ru рядом. Источники, которые не пускают российские IP (Remotive), — через
  `WS_PROXY_URL` и `use_proxy = true` у этого источника.
- **Чистка базы:** раз в сутки удаляются выполненные задачи старше 30 дней, кэш ответов ИИ старше 90 дней,
  сырые данные вакансий старше 30 дней и векторы старше `keep_days`. Сами тексты вакансий пока не удаляются.
- **Ноутбук вместо VPS** тоже подходит, но поиск по расписанию, бот и автоотклики работают, только пока он включён.

## CD: автоматическая выкатка

Каждый пуш в `main` → GitHub Actions (`.github/workflows/deploy.yml`) прогоняет тесты и заходит на сервер по
SSH отдельным ключом, который умеет только запускать `scripts/deploy.sh` (принудительная команда в
`authorized_keys`). Скрипт ставит нужный коммит, зависимости и миграции, перезапускает службу и, если
приложение не поднялось за минуту, откатывается на прошлый коммит.

Настройка (один раз): на сервере у пользователя `worksaas` — remote `github` на этот репозиторий,
право `sudo systemctl restart worksaas` без пароля, публичный ключ CI в `~/.ssh/authorized_keys` с
`command="/home/worksaas/app/scripts/deploy.sh",restrict`; в секретах репозитория — `DEPLOY_HOST`,
`DEPLOY_KEY` (приватный ключ), `DEPLOY_KNOWN_HOSTS` (`ssh-keyscan` сервера). Без секретов выкатка
пропускается. Вручную на сервере: `scripts/deploy.sh <sha коммита main>`.

## Прокси

`WS_PROXY_URL` в `.env` + `use_proxy = true` у нужного провайдера или источника — так через прокси
можно пустить только LLM, а hh.ru оставить напрямую. HTTP(S)-прокси; для SOCKS5 у httpx нужен
`pip install "httpx[socks]"` (работу SOCKS с Anthropic SDK не проверял). Поддержка прокси на
реальном прокси не проверялась.

## Разработка

```bash
pip install -e ".[dev]"
pytest                    # fake-LLM и поддельный Telegram: сеть и деньги не нужны
alembic revision --autogenerate -m "..."   # после изменения моделей в app/models
```

В `.claude/agents/` лежат агенты-критики для Claude Code (ревью кода, безопасность, архитектура,
промпты, UX, тесты, продукт) — см. `CLAUDE.md`, когда какого запускать.
